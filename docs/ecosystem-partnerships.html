Soroban Cookbook

Ecosystem Partnerships

The Soroban Cookbook is a community project: its examples, templates, and guides are more useful when the projects that ship real contracts are visible inside them. This page records who we collaborate with, what we do together, and how to join in.

1. Partnership model

We keep partnerships lightweight and reversible so that neither side is blocked:

LevelWhat it meansWhat we ask
Pattern userA project that follows patterns documented hereA link back, or a mention in their README
Case studyA project whose experience is written up as a case studyA short interview (30 minutes)
Content partnerA project that contributes examples, guides, or reviewAn ongoing review loop on their docs
Event partnerA project that co-hosts calls, workshops, or demosA shared session on the monthly call

Every relationship starts at Pattern user and is upgraded only when the other side asks for it. There are no exclusivity clauses, and no partner logo appears in this repository without a written confirmation from that project’s maintainer.

Joint content rules

  • Every joint document names the contributing project and links back to it.
  • Code in joint content stays canonical to this repository: examples remain buildable here, and external projects are linked rather than forked.
  • Corrections from partners land as pull requests against this repository, not as patches posted elsewhere.

5. Cross-promotion

Cross-promotion is reciprocal and cheap to maintain:

  • Cookbook → partner. A project appears in SHOWCASE.md or this page, and its cookbook usage is described precisely (which patterns, which guide).
  • Partner → cookbook. We ask for exactly one thing: a line in the partner’s README linking to the specific page they used, for example examples/advanced/15-reentrancy-guard or book/src/docs/storage-pitfalls.md.
  • Announcements. Demonstrations are scheduled into the monthly community call and summarized afterwards in the repository.
  • Discovery. Featured work is surfaced in three places so no single channel is a gatekeeper: this page, SHOWCASE.md, and Featured Projects.
  • Opt-out. Any project can ask to be removed from all listings; we remove it in the next pull request without discussion.

7. How to propose a partnership

  1. Open an issue in this repository using the partnership template: project name, links, what you built, and which cookbook patterns you used.
  2. Confirm the link-back. Ask for one line in your README linking to the page you used. That is the whole requirement for the Pattern user level.
  3. Pick a level from the table in Partnership model.
  4. Agree on a cadence. One showcase slot per month, or one review pass per release, whichever is realistic for you.
  5. We write it down. A case study, a listing update, or a joint content PR lands in this repository so the collaboration is public and durable.

We also accept the reverse: if you are a maintainer of another project and want to send your users to a cookbook page, tell us which one and we will make sure the page answers the question they are asking.
